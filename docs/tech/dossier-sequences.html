Runtime Sequence Diagrams

The dynamic choreography behind the static model — how data and control actually flow at runtime. Each names the classes it touches (open them in the Class Explorer).

Illustrative
All bands, weights and cut-points on this page are literature/guideline-anchored examples and must be re-verified and cohort-adjusted before any production use (Conventions §5.6). This is design documentation, not a validated medical device.

Measurement ingest → PureScore recompute

sequenceDiagram
  autonumber
  participant Src as Lab/Wearable
  participant API
  participant Ing as IngestionWorker
  participant MS as MarkerService
  participant CB as CohortBlend
  participant PB as PersonalBaseline
  participant PA as PillarAggregator
  participant RS as ReservoirSystem
  participant SE as ScoringEngine
  participant DB as Datastore
  Src->>API: POST /v1/measurements (value, source, tier)
  API->>Ing: enqueue (idempotency-key)
  Ing->>MS: r_clin = band penalty (Doc03 s1)
  MS->>CB: max(r_clin, phi*cohort) (s2)
  CB->>PB: + kappa_resp*tanh(z/2) (s2b)
  PB->>RS: update B_j (inflow/leak/kappa_jl)
  RS->>PA: B_tilde_k
  PA->>SE: R_k (gamma-mean + rho*B_tilde)
  SE->>SE: critical cascade (cap<=40)
  SE->>DB: persist snapshot + CompanionVector
  SE-->>API: ScoreRecomputed event

Classes: Measurement, InputStream, TrustTier, Marker, CohortStat, PersonalBaseline, Pillar, ReservoirSystem, PureScore, CompanionVector, Explanation

Wearable anomaly → D22 confirmation → escalation

sequenceDiagram
  autonumber
  participant W as Wearable
  participant API
  participant G as ConfirmationGate
  participant EW as EarlyWarning
  participant CC as CriticalCascade
  participant GV as Governance
  W->>API: anomaly (SpO2 88, consumer tier)
  API->>G: trust-tier check (D22)
  alt consumer/inferential tier
    G->>EW: Watch/Advisory only (no cascade)
  else clinical-grade or corroborated
    G->>CC: fire critical cascade
    CC->>GV: escalate (emergency/urgent)
    GV-->>API: clinician + crisis pathway
  end

Classes: WearableMetric, TrustTier, EarlyWarning, CriticalCascade, Governance, CompanionVector

Question answered → pillar & reservoir update

sequenceDiagram
  autonumber
  participant App
  participant QS as QuestionService
  participant DEP as DependencyEngine
  participant RESP as ResponseScorer
  participant PA as PillarAggregator
  participant RS as ReservoirSystem
  App->>QS: GET /questions/next
  QS->>DEP: filter by applicability + prerequisites
  DEP-->>App: next question (ref)
  App->>RESP: POST /responses (answer)
  RESP->>PA: signed pillar weights
  RESP->>RS: signed reservoir inflows
  RESP-->>App: ScoreRecomputed + maybe validated-PRO trigger

Classes: Question, QuestionBank, Response, Dependency, Applicability, Pillar, Reservoir, PureScore, ValidatedPRO

Daily top-5 nudge loop

sequenceDiagram
  autonumber
  participant Sch as Scheduler
  participant NE as NudgeEngine
  participant AC as ActionCatalogue
  participant SF as SafetyFilter
  participant App
  participant AD as Adherence
  Sch->>NE: build daily plan
  NE->>AC: candidate actions (Doc16)
  AC->>SF: contraindication filter
  SF->>NE: U_a = impact*adherence*ease (dPureScore@h)
  NE-->>App: top-5 positive-delta actions
  App->>AD: action completed
  AD->>NE: opens valve -> reservoir inflow (loop)

Classes: NudgeEngine, Action, Adherence, Valve, ReservoirSystem, PureScore, Goal

Acute event → weight override → revert

sequenceDiagram
  autonumber
  participant Ev as LifeEvent
  participant AE as AcuteEvent
  participant PS as PatientState
  participant SE as ScoringEngine
  Ev->>AE: trigger (m_acute spike)
  AE->>PS: enter AcuteMode
  AE->>SE: override pillar weights
  SE->>SE: recompute (acute frame)
  Note over PS,SE: recovery + hysteresis
  PS->>SE: revert to Baseline weights

Classes: AcuteEvent, PatientState, Pillar, ReservoirSystem, PureScore, CarePlan

Daily reservoir state update (MONIAC)

sequenceDiagram
  autonumber
  participant Sch as Scheduler
  participant RS as ReservoirSystem
  participant IM as InterferenceMatrix
  participant PA as PillarAggregator
  Sch->>RS: tick (delta = 1 day)
  RS->>RS: inflow_j(markers, behaviours)
  RS->>RS: leak lambda_j*(B-B*)
  RS->>IM: coupling kappa_jl*sat(B_l)
  IM->>RS: clamp [0, B_max]
  RS->>PA: B_tilde_k -> pillar risk

Classes: ReservoirSystem, Reservoir, InterferenceMatrix, Valve, Pillar

Appendix K — Onboarding & First-Run Intake Flow

The first-run experience the audit found nobody owned: the ordered sequence of screens from install to first score, the full demographic field-set, the question-side cold-start (minimal bootstrap set → progressive profiling), and where consent & device-pairing sit. It hands off to the question bank (Appendix E), persona determination (Appendix I), goals (Appendix J) and the Onboarding sub-machine on the patient state machine.

Illustrative
All bands, weights and cut-points on this page are literature/guideline-anchored examples and must be re-verified and cohort-adjusted before any production use (README §5.6). This is design documentation, not a validated medical device.

Consent first
No PII or health data is captured before the privacy & data-use consent step; device-pairing and EHR-connect gate the streams they unlock (Doc 11 · Doc 18 · D22). The actuarial layer is firewalled and off by default (Doc 10).

Question-side cold-start & progressive profiling · closes F11

Rule
Bootstrap with the smallest item set that (a) seeds an initial multi-pillar score and (b) resolves a persona; defer the rest to progressive profiling.
Bootstrap itemPillarWhy it earns its place
PHQ-2MCSdepression screen → MCS + crisis safety
GAD-2MCSanxiety screen → MCS
Sleep duration/regularitySLP→ SLP + persona (shift/new-parent)
IPAQ-SF (1 item)FIT→ FIT + persona (sedentary/athlete)
AUDIT-CHEP→ HEP/MCS + persona (social-drinker)
Smoking statusCV→ CV/INF cross-cutting + persona
Diet-quality (1 item)NUT→ NUT/MET + persona
  • session 1: demographics + goal seed + bootstrap PROs → first score (low confidence)
  • session 2plus: remaining bank by priority P1→P5, gated by sex/age/life-stage/persona applicability (Appendix E DAG)
  • triggered: out-of-range markers / persona changes unlock targeted deep-dive items
  • refresh: validated PROs re-administered on their cadence (Appendix C); confidence grows with coverage (Doc 14 ignition)

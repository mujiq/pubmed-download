Appendix B — Wearable Metrics & Trust Tiers

Every wearable signal, its abstraction layer (raw → aggregated → derived), its trust tier (D22), the confidence weight q_source it earns, the pillars it feeds and representative devices. See Doc 07 and Doc 06 §2.

All bands, weights and cut-points on this page are literature/guideline-anchored examples and must be re-verified and cohort-adjusted before any production use (README §5.6). This is design documentation, not a validated medical device.

Safety rule (D22)
A consumer or inferential wearable anomaly may raise Watch/Advisory but cannot drive a red/critical without a clinical-grade confirmation (CGM / validated cuff / single-lead ECG, or a lab). (Doc 05 §3.4)

Terra — the ingestion API
PureScore ingests wearable data through Terra, the aggregation API that normalizes 30+ devices (Apple Health, Google Fit, Oura, Whoop, Garmin, Fitbit, Samsung, Dexcom, Freestyle Libre…) into uniform models. Every signal above arrives via a Terra model; the trust tier and q_source still apply per signal.

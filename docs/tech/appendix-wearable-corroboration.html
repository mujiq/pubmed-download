Appendix L — Wearable Corroboration — question → metric → tolerance (closes F4)

Types the 'wearable-match' stage: the question bank's free-text-ish wearable.<metric> corroborations are normalized to a canonical wearable metric (Appendix B), assigned a typed source channel, and given a per-metric TOLERANCE — the agreement band between the self-reported answer (perceived) and the wearable actual, beyond which a perceived↔actual gap is flagged. This makes stage-3 auditable: every wearable corroboration resolves to a metric + tolerance the gap engine can apply.

Illustrative
All bands, weights and cut-points on this page are literature/guideline-anchored examples and must be re-verified and cohort-adjusted before any production use (README §5.6). This is design documentation, not a validated medical device.
Perceived ↔ actual, with a typed tolerance
flowchart LR
  SR["self-report answer (perceived)"] --> CMP{"|Δ| > tolerance?"}
  WM["wearable metric (actual, Appendix B)"] --> CMP
  CMP -->|yes| GAP["perceived↔actual gap (Appendix F)\nlower Confidence (Doc 12)"]
  CMP -->|no| OK["corroborated → higher Confidence"]
Tolerance
|perceived − actual| > tolerance ⇒ flag a perceived-vs-actual gap (Appendix F) and lower Confidence (Doc 12). Consumer/inferential metrics never drive a band on their own (D22).
Normalized
Casing/alias variants collapse to one id (wearable.hrv = wearable.HRV; wearable.SpO2 = wearable.spo2; wearable.resting_hr = wearable.resting_HR; wearable.steps ≈ wearable.step_count).

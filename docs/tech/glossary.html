Glossary · one canonical term per concept, across clinical · product · technical

A single source of truth for what every term means and which spelling is canonical. Each entry is tagged by lens — Clinical term · Product / Mobile-UI term · Technical / engine term. This page also powers the wiki-wide hover tooltips (data/glossary.json → assets/acronyms.js).

Lenses
ClinicalProduct / UITechnical

Standardization rulings

Where one concept had several names across the wiki, this is the agreed canonical term. Variants are retained only as aliases. (Recorded, not yet mass-applied to body text.)

Product / UI   First-time setup flow
Canonical: Onboarding aliases: first-run, sign-up, registration
Use Onboarding for the one-time first-run experience (demographics, consent, cold-start). 'First-run' is an informal alias only. Onboarding is the first phase of Intake.
Product / UI   Ongoing data collection (the question/answer system)
Canonical: Intake
Bare Intake = the product data-collection umbrella (Onboarding + Progressive profiling + Check-ins). The clinical sense must always be qualified: write dietary intake or reservoir inflow, never bare 'intake'.
Product / UI   Collecting more user attributes over time
Canonical: Progressive profiling aliases: progressive data (collection), staged profiling, progressive disclosure
Use Progressive profiling for gradually gathering member attributes/demographics across sessions. The data-quality chapter is renamed to Data quality & graceful degradation so 'progressive' no longer collides with the degradation pipeline.
Product / UI   System↔user interaction
Canonical: Nudge (outbound) / Check-in (inbound) aliases: micro-action, daily action, prompt
Nudge = a system→user prompt suggesting a behaviour/action (the nudge engine). Check-in = a system→user prompt requesting data (mood/stress/adherence self-report). An adherence check-in is a check-in confirming a prescribed action was done. OOUX cross-walk: at the member surface a Nudge is a Notification(type=nudge); the 'nudge engine' = Action Funnel + RewardFunction + ClinicalIntelligence. Check-ins follow a max-3/day budget.
ClinicalProduct / UI   Care construct
Canonical: Care pathway (template) / Care plan (prescribed) / Protocol (member) aliases: treatment plan, care program
Care pathway = the standardized condition-level clinical template (IEAT lifecycle) — do NOT call it a 'protocol'. Care plan = the clinician-prescribed instance generated for one member from a pathway (their bundle of interventions + goals). Protocol = the member-authored lifestyle plan-per-goal (OOUX). Three distinct constructs along the prescriber axis; reserve the word 'protocol' for the member's plan only.
Product / UITechnical   Desired aim
Canonical: Goal (user) / Target (setpoint) aliases: objective, aspiration
Goal = the member-stated aspiration that personalizes scoring/actions (drives m_k^goal). Target = a technical/clinical setpoint or threshold (reservoir B^target, calibration target, validation target population). Never use 'target' to mean a user goal. PersonalGoal is the OOUX object name for a member's Goal.
ClinicalTechnical   Questionnaire family
Canonical: Instrument (set) · screener (subtype) · PRO (channel) aliases: questionnaire, survey, self-report, assessment (misuse)
Instrument = any validated question set (absorbs 'questionnaire'/'survey'). Screener = a defined subtype: a short triage instrument (e.g. PHQ-2). PRO (patient-reported outcome) = the input channel/modality (absorbs 'self-report'). Assessment is reserved for a clinical risk-assessment process — never for a questionnaire.
TechnicalProduct / UI   The 12 health systems
Canonical: Pillar aliases: domain (evidence-ID token only), health system, axis
Pillar is the one canonical term for the 12 systems in all prose. Domain is permitted ONLY as the frozen field/ID token in the evidence registry (EVD-<DOMAIN>-…), where renaming would break stable keys. OOUX: its 4 'PureScore Pillars' (Risk/Reserve/Lifestyle/Vitality) are score facets — an optional roll-up ABOVE the 12, never a replacement.
ClinicalTechnical   A measured/scored quantity
Canonical: Marker aliases: biomarker, metric (derived only), signal (informal)
Marker = any scored input (lab, wearable or PRO). 'Biomarker' is an alias of marker. Metric is reserved for a derived/computed value (e.g. HRV from raw beats). 'Signal' is informal — avoid in spec prose. Adopt the OOUX object split MarkerDef (definition) / MeasuredValue (a reading) / ReferenceRange (bands) — the wiki already mirrors it (MarkerDef / Measurement / ReferenceDist). 'Biomarker' is the My-Health product-surface alias.
Product / UIClinical   The person / app actor
Canonical: Member aliases: patient (clinical prose), user (legacy/product)
Member is the canonical term for the person the system serves (OOUX's primary object). Use Member in product and user-facing prose. Patient stays only in genuinely clinical framing and in fixed terms — patient-reported outcome, patient safety, in-/out-patient — which are NEVER renamed. Internal code identifiers (the PatientState class, patient data keys, patient_app) keep their names to avoid breaking the engine; this ruling records the mapping. 'User' = legacy/technical (UX, end-user, decision-log author) — leave as-is.
Product / UITechnical   The headline banded number
Canonical: Accuracy aliases: confidence (OOUX sense)
Accuracy = the headline banded number the member sees (OOUX calls this same number 'Confidence'). Its named sub-components: Confidence = trustworthiness of the inputs; Sufficiency = how complete the data is. One number, one word — Accuracy; reserve 'Confidence' for the sub-component (and the statistical sense), never the headline band.
TechnicalProduct / UI   Data-sufficiency / trust level
Canonical: Sufficiency aliases: KnowledgeLevel (OOUX)
Sufficiency = how much usable data backs the score (cohort-fallback included). OOUX's KnowledgeLevel is the product-surface alias for the same idea.
ClinicalProduct / UI   Biological-age outcome
Canonical: BioAge aliases: HealthAge (OOUX/product)
BioAge (biological age) is the canonical outcome term; HealthAge is the product-surface alias.
Product / UITechnical   Action-selection pipeline objects
Canonical: Action Funnel / Insight / EnhancementAction / Value of Information
Adopt the OOUX names for the (previously unnamed) action-selection pipeline: Action Funnel = the selection/ranking stages; Insight = the nudge-card payload; EnhancementAction = a MEASURE/CLINICAL nudge; Value of Information = the ΔAccuracy-per-effort ranking. Pure relabel — no math change.

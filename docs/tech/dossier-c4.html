C4 Architecture (Container / Component)

How the domain model runs as a system: external actors, services (containers), their components, and the datastores. Each class maps to a component (see its Class Explorer page).

Illustrative
All bands, weights and cut-points on this page are literature/guideline-anchored examples and must be re-verified and cohort-adjusted before any production use (README §5.6). This is design documentation, not a validated medical device.

Containers & components

Patient App (web/mobile) (client)

score, companion vector, daily nudges, questionnaires

Doctor's Board (admin) (client)

ranges, weights, personas, governance sign-off

API Gateway (service)

auth, idempotency, routing, rate limits

Ingestion Service (workers)

stream normalization, trust-tier tagging, dedup

Scoring Engine (service)

marker→pillar→PureScore + companion vector

question bank, dependency DAG, scheduling

DependencyEngineApplicabilityResponseScorerPROBridge

Nudge Service (service)

top-5 ranking, safety filter, adherence

ActionCatalogueSafetyFilterRankerAdherenceTracker

Model Registry (service)

versioned constants, calibration, release gates

ConstantsStoreCalibratorValidationHarness

Datastore (postgres + TSDB)

relational + time-series (markers, reservoirs)

Audit Store (append-only)

immutable decisions, escalations, model bumps

Actuarial Layer (firewalled)

gated, separate consent, no protected-class proxy

Integrations (webhooks/feeds)

wearable webhooks, lab feeds (HL7/FHIR)

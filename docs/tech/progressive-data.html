Progressive Data & Graceful Degradation · missing → cohort → lower accuracy → nudge

PureScore never blocks on missing data. When any input — a lab, a wearable metric, a clinical reading, a lifestyle answer, a personal baseline, or a goal — is missing, stale, decayed or invalid, the system substitutes a cohort statistic (age×sex×life-stage median/mean, D33) so the score stays continuous, lowers the reported Accuracy, widens the forecast, flags the substitution in the companion vector, and nudges the user over time to fill the gap. Single sources: data/degradation-model.json · data-completeness-nudges.json.

Illustrative
All bands, weights and cut-points on this page are literature/guideline-anchored examples and must be re-verified and cohort-adjusted before any production use (Conventions §5.6). This is design documentation, not a validated medical device.
Safety invariant (load-bearing)

A COHORT-SUBSTITUTED value is informational-only. It MAY lower a score and widen uncertainty, but it can NEVER (a) raise Confidence or Accuracy, (b) trigger a red/critical pillar floor (R_crit), or (c) fire a clinical Early-warning Advisory/Alert. Only a REAL, in-date, VALID measurement can do those. This extends D22 (trust tiers) and preserves the critical-marker gate, which already requires state=present with a real value.

1 · Data states

StateMeaning & effect
presentreal, in-date, valid measurement — full weight & confidence (q_source).
stalereal but older than the metric's fresh-within SLA — confidence decays q_source·exp(−Δt/τ); value blends toward neutral as it ages.
decayedstale beyond stale_dt_days — effectively non-informative; treated as missing for the centre but kept for provenance.
invalidfails the plausibility gate (out-of-physiological-range / implausible) — REJECTED to quarantine, then treated as missing (cohort-substituted), never allowed to saturate the risk function.
missingno usable value — cohort statistic substituted at low confidence (per input type below).

Why some inputs were dropped before

Clinical & wearable markers were previously dropped when missing (never fabricate a blood pressure). Under the universal-but-safe model they now cohort-fill for scoring continuity at very low confidence — but the safety invariant keeps a cohort value from ever triggering a red/critical pillar or a clinical alert, so the conservatism is preserved where it matters.

3 · Accuracy & the widening forecast

Reported Accuracy

Accuracy A_k = Confidence_k · Sufficiency_k · (1 − λ·cohortFillFraction_k), bounded [0,1], reported as a %.

Confidence = source quality × freshness (q·exp(−Δt/τ)); Sufficiency = fresh-patient-data fraction; cohortFillFraction = share of the pillar's weight currently met by cohort substitution; λ ≈ 0.5 (expert-prior).

Confidence = is present data trustworthy? Sufficiency = is data present? Accuracy = the combined, cohort-penalised headline the user sees ('reported with lower accuracy').

Forecast cone

Trajectory forecast widens with uncertainty: point days-to-threshold T̂ from the robust slope; half-width H = k · (σ_t / A) · √(horizon), where σ_t = pillar Volatility (companion #8) and A = Accuracy. Shown as a CONE, not a line.

high accuracy → tight cone (T̂ ± 3d); low accuracy / high volatility / heavy cohort-fill → wide cone (T̂ ± 15d) or 'forecast withheld' when A < a floor.

below an accuracy floor the forecast is shown as a range only or suppressed with 'need more data', never a confident point.

5 · Invalid-value handling

Detect: per-marker plausibility gate (min/max from wearable-metrics.json / range-variations) — e.g. HR>220, SpO₂<70, negative durations
Action: REJECT → quarantine-with-context → treat the marker as missing → cohort-substitute + flag; never let an implausible value saturate the continuous risk function

Gap: the scoring engine has no INVALID state today (only missing/stale) — invalid values currently saturate; this model adds the gate

Escalation & continuity

Offer at a base cadence. On dismiss → back off (decreasing cadence). As the underlying data AGES past its Freshness-SLA stale-after, BUMP the CTA's ranking priority and cadence (a 95-day-old ApoB outranks a 30-day-old one). Cap frequency (no spam). After N ignores → StopOutreach (engagement state machine Dormant→ReEngage→StopOutreach).

the loop runs continuously: every score render re-evaluates cohort-fill % and re-ranks completeness CTAs, so as the user closes one gap the next-best one surfaces — progressive data collection over time.

User-facing “Data Health” surface
  • Data completeness % and Accuracy % beside the PureScore
  • the top 1–3 next-best inputs to add (ranked by ΔAccuracy-per-effort)
  • which pillars are running on cohort estimates ('CV is 42% estimated — add ApoB')
  • the mobile 'Confidence & Trust' baseline screen already widens bands over gaps (baseline-mob-viz) — extend it with these CTAs

7 · Remaining gaps (loop)

  • Engine wiring: extend assets/engine.js imputation to wearable/clinical/PRO channels with per-channel q_impute, plus the invalid-value plausibility gate (today only labs impute; engine has no invalid state).
  • Companion vector: add Cohort-fill %, Accuracy and Forecast-band as live dims in Doc 05 §4 / the calc-explorer, not just this spec.
  • Per-marker volatility-aware τ (recency half-life) so staleness decays at the right rate per metric.
  • The “Data Health” user surface + the data-completeness nudge class are specified here but not yet built into the mobile prototype or the nudge engine catalogue (adherence.json).
  • ΔAccuracy-per-effort ranking needs a real information-gain estimate, not the effort heuristic used here.
